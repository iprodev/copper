on-device processing actually works now, two services give you working, simpler files, and saving on iphones is simpler.

- **on-device processing works**: the server sent the files of the browser's ffmpeg with the wrong type, so every browser refused to run it, and every file that needed merging or converting was quietly made on the server instead.
- **instagram reels are videos again**: some reels were saved as their cover image instead of the video. fetchr now reads the post from its page, where the video is, and never saves a cover in place of a video.
- **pornhub works in more countries**: where the site blocks its streaming files because of age verification laws, fetchr downloads the video as a single mp4 file instead, which still works there.
- **xvideos**: when the quality you asked for also exists as a single mp4 file (usually up to 480p), that file is downloaded instead of the streaming version. it's simpler, and can continue where it stopped if it's interrupted.
- **iphone and ipad**: the share sheet gets the video itself now (with "save video"), not a link to it. with on-device processing on (the default), your browser downloads every file first, even ones that need no processing.
