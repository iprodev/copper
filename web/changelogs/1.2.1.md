---
title: "more reliable on-device processing"
date: "22 November, 2026"
---

a few fixes for on-device processing, where your browser merges and converts files instead of the server.

- **long queues work now**: links to files only stay valid for a short time, so files that waited in the processing queue behind bigger ones used to fail. they get fresh links right before they start now.
- **the server takes over when your browser can't**: if processing in your browser fails (for example, because it runs out of memory), the file is processed on the server instead of showing an error.
- **no more frozen tabs**: in some browsers (like firefox's private windows), downloads of files with an unknown size could freeze the tab.
- downloads that fail because of a network hiccup are tried again with a short pause, and the half-downloaded parts don't stay in your browser's storage.
- **interrupted downloads continue where they stopped** instead of starting over.
- **the next file downloads while the one before it is being processed**, so long queues finish sooner.
- **your browser's free space is checked first**: if a file won't fit, the server processes it instead of failing halfway.
- **videos split into many small parts** (like on bluesky and loom) are put together in your browser now, too.
- **chrome on android merges video and audio itself**; converting (audio, gifs) is still left to the server, since it's too slow on phones.
