# راهنمای نصب fetchr روی سرور

این پوشه همه‌چیز را برای نصب fetchr روی یک VPS دارد: سایت، API، Cloudflare WARP و سازنده‌ی توکن برای یوتیوب، و ربات تلگرام.
نصب طوری است که **به سایت‌ها و تنظیمات دیگر سرور دست نمی‌زند**.

## چه چیزی کجا نصب می‌شود

```
nginx (روی خود سرور)
 ├─ سایت‌های دیگر شما            ← دست نمی‌خورند
 ├─ fetchr.download              ← فایل‌های سایت در /var/www/fetchr
 └─ api.fetchr.download          ← 127.0.0.1:9000

docker (پوشه‌ی /opt/fetchr)
 ├─ api                          ← فقط روی 127.0.0.1، از بیرون در دسترس نیست
 ├─ youtube-pot                  ← توکن یوتیوب، بدون پورت بیرونی
 ├─ warp                         ← پراکسی socks5 فقط برای کانتینرهای دیگر
 └─ bot (اختیاری)                ← ربات تلگرام
```

- اسکریپت نصب فقط دو فایل جدید به nginx اضافه می‌کند (`fetchr-web.conf` و `fetchr-api.conf`). اگر تنظیمات جدید با `nginx -t` خطا بدهد، همان فایل‌ها پاک می‌شوند و nginx اصلاً reload نمی‌شود.
- WARP داخل کانتینر خودش است و فقط ترافیک یوتیوب از آن رد می‌شود. شبکه‌ی سرور و سایت‌های دیگر تغییری نمی‌کنند.
- بدون پرسیدن از شما چیزی نصب نمی‌شود (داکر، nginx، certbot).

## پیش‌نیازها

1. یک VPS با مجازی‌سازی **KVM** و Ubuntu 22.04/24.04 یا Debian 12 (حداقل ۲ هسته و ۲ گیگ RAM).
2. دو رکورد DNS از نوع A که به IP سرور اشاره کنند:
   - `fetchr.download`
   - `api.fetchr.download`
3. پورت‌های ۸۰ و ۴۴۳ در فایروال باز باشند (مثلاً `ufw allow 'Nginx Full'`).

> **اگر دامنه در Cloudflare است:** برای `api.fetchr.download` حالت **DNS only** (ابر خاکستری) را بگذارید. فایل‌ها از API رد می‌شوند و عبور ویدیو از پراکسی رایگان Cloudflare کندتر است و ممکن است با قوانین Cloudflare مشکل داشته باشد. برای `fetchr.download` هر دو حالت مشکلی ندارد. اگر API پشت پراکسی Cloudflare باشد هم IP واقعی کاربران درست تشخیص داده می‌شود.

## نصب

```bash
git clone https://github.com/iprodev/fetchr.git
cd fetchr/deploy
sudo ./install.sh
```

اسکریپت این کارها را انجام می‌دهد و هر جا لازم باشد از شما می‌پرسد:

1. بررسی سرور: داکر، nginx، معتبر بودن تنظیمات فعلی nginx، و وجود `/dev/net/tun` برای WARP.
2. پرسیدن دامنه‌ها و توکن ربات تلگرام (اختیاری)، و ساختن تنظیمات در `/opt/fetchr/.env`.
3. دانلود فایل‌های سایت از آخرین نسخه (release) در گیت‌هاب.
4. اضافه کردن دو دامنه به nginx.
5. اجرای کانتینرها و بررسی اینکه API و WARP کار می‌کنند.
6. روشن کردن نظارت خودکار (اختیاری).
7. گرفتن گواهی رایگان https از Let's Encrypt با certbot.

اگر پورت ۹۰۰۰ قبلاً استفاده شده باشد، اسکریپت خودش یک پورت آزاد دیگر انتخاب می‌کند.

## بررسی بعد از نصب

```bash
cd /opt/fetchr

# وضعیت کانتینرها
sudo docker compose ps

# آیا warp وصل است؟ (باید warp=on ببینید)
sudo docker compose exec warp curl -s --socks5-hostname 127.0.0.1:1080 https://www.cloudflare.com/cdn-cgi/trace | grep warp

# لاگ‌ها
sudo docker compose logs -f api
```

بعد سایت `https://fetchr.download` را باز کنید و یک لینک یوتیوب امتحان کنید.

## ربات تلگرام

### راه‌اندازی

1. در تلگرام به [@BotFather](https://t.me/BotFather) پیام دهید، `/newbot` را بزنید و توکن را کپی کنید.
2. شناسه‌ی عددی تلگرام خودتان را از ربات [@userinfobot](https://t.me/userinfobot) بگیرید (برای پنل مدیریت).
3. فایل `/opt/fetchr/.env` را باز کنید و این خط‌ها را تنظیم کنید:
   ```
   COMPOSE_PROFILES=bot
   BOT_TOKEN=توکن-ربات
   BOT_ADMIN_IDS=شناسه‌ی-شما
   ```
   برای چند مدیر، شناسه‌ها را با کاما جدا کنید.
4. اجرا کنید:
   ```bash
   cd /opt/fetchr && sudo docker compose up -d
   ```

اگر هنگام نصب توکن را وارد کرده باشید، اسکریپت این کارها را خودش انجام داده است.

### امکانات برای کاربران

- **انتخاب زبان:** کاربر جدید با `/start` اول زبان (فارسی یا انگلیسی) را انتخاب می‌کند و بعد پیام خوش‌آمد و دکمه‌های «راهنما»، «تنظیمات» و «زبان» را می‌بیند.
- **انتخاب کیفیت با دکمه:** بعد از فرستادن لینک، کاربر کیفیت را انتخاب می‌کند: 1080p، 720p، 480p، 360p یا فقط صدا.
- **کیفیت پیش‌فرض:** در «تنظیمات» می‌شود یک کیفیت ثابت انتخاب کرد تا هر بار پرسیده نشود.
- **آلبوم:** چند عکس و ویدیوی یک پست به‌صورت آلبوم فرستاده می‌شود.
- **ارسال فوری لینک‌های تکراری:** اگر لینکی قبلاً با همان کیفیت فرستاده شده باشد، تلگرام همان فایل را فوری دوباره می‌فرستد، بدون دانلود دوباره. خود لینک ذخیره نمی‌شود، فقط یک کد یک‌طرفه از آن.
- **امضا زیر فایل‌ها:** به‌طور پیش‌فرض `📥 @ربات‌شما`، از پنل مدیریت قابل تغییر یا حذف است.
- **جایگاه در صف:** وقتی ربات شلوغ است، کاربر می‌بیند نفر چندم صف است.
- **دعوت دوستان:** هر کاربر با `/invite` یا دکمه‌ی «دعوت دوستان» لینک دعوت اختصاصی خودش را می‌گیرد. اگر سهمیه‌ی روزانه روشن باشد، به ازای هر دعوت سهمیه‌ی بیشتری می‌گیرد.
- **حالت inline:** کاربر در هر چتی می‌نویسد `@ربات‌شما لینک` و فایل‌هایی که قبلاً گرفته شده‌اند همان‌جا فرستاده می‌شوند. اگر فایل هنوز گرفته نشده باشد، دکمه‌ای کاربر را به ربات می‌برد تا دانلود شود. برای روشن کردن این حالت، در [@BotFather](https://t.me/BotFather) دستور `/setinline` را بزنید.
- **گروه‌ها:** اگر از پنل مدیریت روشن شود، ربات در گروه‌ها به `/dl لینک` جواب می‌دهد (یا `/dl` در جواب به پیامی که لینک دارد). به بقیه‌ی پیام‌های گروه کاری ندارد.

### رعایت محدودیت‌های تلگرام

تلگرام برای ربات‌ها محدودیت ارسال دارد: حدود ۳۰ پیام در ثانیه در کل، حدود ۱ پیام در ثانیه در هر چت خصوصی و حدود ۲۰ پیام در دقیقه در هر گروه. ربات‌هایی که این حدها را رعایت نکنند، محدود می‌شوند.

همه‌ی پیام‌ها، ویرایش‌ها و فایل‌های ربات از یک صف مرکزی رد می‌شوند که این حدها را رعایت می‌کند:
- در کل حداکثر ۲۵ درخواست در ثانیه، کمی کمتر از حد تلگرام.
- در هر چت خصوصی حداکثر یک پیام در ثانیه، و در هر گروه یک پیام در هر ۳ ثانیه.
- پیام‌های کاربران همیشه جلوتر از پیام همگانی فرستاده می‌شوند. پس پیام همگانی برای هزاران نفر، ربات را برای کاربران کند نمی‌کند.
- اگر چند ویرایش یک پیام وضعیت (مثل «در حال دانلود ۳ از ۱۰») در صف منتظر باشند، فقط آخرینشان فرستاده می‌شود.
- اگر تلگرام باز هم خطای «درخواست زیاد» (429) بدهد، ربات دقیقاً همان مدتی که تلگرام می‌گوید صبر می‌کند و دوباره امتحان می‌کند.

### پنل مدیریت

مدیرها با فرستادن `/admin` به ربات، پنل مدیریت را می‌بینند:

- **📊 آمار:** تعداد کاربران (فعال، کسانی که ربات را بلاک کرده‌اند، مسدودشده‌ها، کاربران جدید)، تعداد دانلودهای امروز، هفته و کل، و سرویس‌های پرکاربرد.
- **📣 پیام همگانی:** هر پیامی بفرستید (متن، عکس، ویدیو، فایل یا پیام فورواردشده)، پیش‌نمایش را ببینید و تأیید کنید تا برای همه‌ی کاربران فرستاده شود. کسانی که ربات را بلاک کرده‌اند از دفعه‌ی بعد کنار گذاشته می‌شوند.
- **📢 عضویت اجباری:** کانال‌هایی که کاربران باید قبل از استفاده در آن‌ها عضو شوند. کانال را با شناسه (`@mychannel`)، لینک یا فوروارد یک پیام از کانال اضافه کنید. **ربات باید در کانال مدیر باشد.** مدیرهای ربات لازم نیست عضو شوند.
- **👋 پیام خوش‌آمد:** متن دلخواه برای خوش‌آمد فارسی و انگلیسی، یا برگشت به متن پیش‌فرض.
- **🎟 سهمیه:** تعداد دانلود مجاز هر کاربر در روز (۰ یعنی نامحدود، که پیش‌فرض است) و تعداد دانلود اضافه به ازای هر دعوت (پیش‌فرض ۵).
- **⭐️ کاربر ویژه:** کاربران ویژه محدودیت سهمیه ندارند. با شناسه‌ی عددی اضافه می‌شوند و با یک منفی قبل از شناسه برداشته می‌شوند.
- **✍️ امضای فایل‌ها:** متن زیر فایل‌ها. با فرستادن `-` امضا حذف می‌شود.
- **👤 مسدود کردن کاربر:** با شناسه‌ی عددی کاربر. برای رفع مسدودیت یک منفی قبلش بگذارید (مثلاً `-123456`).
- **👥 گروه‌ها:** روشن و خاموش کردن کار ربات در گروه‌ها.
- **🛠 حالت تعمیر:** وقتی روشن است، فقط مدیرها می‌توانند از ربات استفاده کنند.
- **💾 پشتیبان:** فرستادن فوری فایل پایگاه داده. جدا از این، هر روز ساعت ۴ صبح (به وقت سرور) پشتیبان خودکار برای همه‌ی مدیرها فرستاده می‌شود. ساعتش با `BOT_BACKUP_HOUR` در `.env` عوض می‌شود (`-1` یعنی خاموش).

**برگرداندن پشتیبان:** فایل `.db` را به‌جای `/opt/fetchr/bot-data/bot.db` بگذارید و ربات را دوباره اجرا کنید:
```bash
cd /opt/fetchr && sudo docker compose stop bot
sudo cp fetchr-bot-YYYY-MM-DD.db bot-data/bot.db && sudo chown 1000:1000 bot-data/bot.db
sudo docker compose up -d bot
```

### حریم خصوصی

لینک‌هایی که کاربران می‌فرستند هیچ‌جا ذخیره یا ثبت نمی‌شوند. ربات فقط این‌ها را نگه می‌دارد:
- شناسه‌ی تلگرام، زبان، تنظیمات و دعوت‌کننده‌ی هر کاربر (برای پیام همگانی و سهمیه)؛
- تعداد دانلود هر کاربر در هفت روز اخیر (برای سهمیه) و تعداد دانلودهای هر سرویس در هر روز؛
- شناسه‌ی فایل‌هایی که تلگرام فرستاده، با یک کد یک‌طرفه از لینک (برای ارسال فوری).

این اطلاعات در `/opt/fetchr/bot-data/bot.db` است.

### ارسال فایل‌های بزرگ‌تر از ۵۰ مگابایت

ربات‌های تلگرام به‌طور عادی فقط تا ۵۰ مگابایت می‌توانند فایل بفرستند. با سرور محلی Bot API این حد به ۲۰۰۰ مگابایت می‌رسد.

**ساده‌ترین راه:** اسکریپت نصب بعد از تنظیم ربات این را می‌پرسد. فقط `api_id` و `api_hash` را از [my.telegram.org](https://my.telegram.org) (بخش API development tools) بگیرید و وارد کنید. بقیه‌ی کارها، از جمله خارج کردن ربات از سرور اصلی تلگرام، خودکار انجام می‌شود.

اگر قبلاً پاسخ «نه» داده‌اید، خط `LOCAL_BOT_API=no` را از `/opt/fetchr/.env` پاک کنید و اسکریپت نصب را دوباره اجرا کنید.

**راه دستی:**

1. در [my.telegram.org](https://my.telegram.org) وارد شوید و از بخش API development tools یک `api_id` و `api_hash` بگیرید.
2. یک بار ربات را از سرور اصلی تلگرام خارج کنید (این آدرس را در مرورگر باز کنید):
   `https://api.telegram.org/botتوکن-ربات/logOut`
3. در `.env`:
   ```
   COMPOSE_PROFILES=bot,bot-api-server
   TELEGRAM_API_ID=...
   TELEGRAM_API_HASH=...
   TELEGRAM_API_URL=http://telegram-bot-api:8081
   ```
4. `cd /opt/fetchr && sudo docker compose up -d`

## نظارت خودکار

اگر هنگام نصب نظارت را روشن کرده باشید، هر ۱۰ دقیقه این موارد بررسی می‌شوند:

| بررسی | اگر مشکل داشت |
|:--|:--|
| API جواب می‌دهد؟ | API دوباره راه‌اندازی می‌شود (حداکثر هر نیم ساعت یک بار) |
| WARP وصل است؟ | WARP دوباره راه‌اندازی می‌شود (حداکثر هر نیم ساعت یک بار) |
| دانلود واقعی یک ویدیوی یوتیوب کار می‌کند؟ | WARP دوباره ثبت‌نام می‌کند تا IP جدید بگیرد (حداکثر هر ساعت یک بار) |
| همه‌ی کانتینرها اجرا می‌شوند؟ | فقط هشدار |
| فضای دیسک پر نشده؟ (بیش از ۹۰٪) | فقط هشدار |

هر وقت چیزی خراب شود یا دوباره درست شود، از طریق ربات به **مدیرهای ربات** (`BOT_ADMIN_IDS`) پیام فرستاده می‌شود. هشدار تکراری فرستاده نمی‌شود.
برای هشدارها، ربات تلگرام باید راه‌اندازی شده باشد.

دستورهای مفید:

```bash
# وضعیت همه‌چیز، بدون تعمیر یا هشدار
sudo /opt/fetchr/monitor.sh --report

# فرستادن یک پیام آزمایشی به مدیرها
sudo /opt/fetchr/monitor.sh --test-alert

# گزارش اجراهای قبلی
sudo journalctl -u fetchr-monitor --since today

# خاموش کردن نظارت
sudo systemctl disable --now fetchr-monitor.timer
```

## تنظیمات

همه‌ی تنظیمات در `/opt/fetchr/.env` است. بعد از هر تغییر:

```bash
cd /opt/fetchr && sudo docker compose up -d
```

چند تنظیم مهم:
- `SERVICE_PROXIES`: سرویس‌هایی که از WARP رد می‌شوند. اگر سرویس دیگری هم IP سرور را بلاک کرد، اضافه‌اش کنید:
  `SERVICE_PROXIES=youtube=socks5://warp:1080,instagram=socks5://warp:1080`
- `RATELIMIT_MAX`: حداکثر درخواست هر کاربر در دقیقه.
- `DURATION_LIMIT`: حداکثر طول ویدیو به ثانیه (پیش‌فرض ۳ ساعت).
- `DISABLED_SERVICES`: سرویس‌هایی که نمی‌خواهید کار کنند.
- `WARP_LICENSE_KEY`: اگر WARP+ دارید.

## به‌روزرسانی

```bash
cd fetchr && git pull
cd deploy && sudo ./install.sh
```

اسکریپت تنظیمات و فایل‌های nginx قبلی را نگه می‌دارد، آخرین نسخه‌ی سایت و image‌ها را می‌گیرد و کانتینرها را دوباره اجرا می‌کند.
سه نسخه‌ی آخر سایت در `/var/www/fetchr/releases` می‌ماند.

## مشکلات رایج

**یوتیوب خطا می‌دهد:** اگر نظارت روشن باشد، این مشکل معمولاً خودکار حل می‌شود. وگرنه اول وصل بودن WARP را بررسی کنید (بالا). اگر یوتیوب IP فعلی WARP را هم بلاک کرده باشد، با ثبت‌نام دوباره IP عوض می‌شود:
```bash
cd /opt/fetchr
sudo docker compose stop warp && sudo rm -rf warp-data/* && sudo docker compose up -d warp
```

**WARP وصل نمی‌شود و در لاگ `open tun` یا `Operation not permitted` می‌بینید:** سرور باید KVM باشد. روی سرورهای OpenVZ/LXC کار نمی‌کند.

**گواهی https گرفته نشد:** مطمئن شوید DNS هر دو دامنه به IP سرور اشاره می‌کند و پورت ۸۰ باز است، بعد:
```bash
sudo certbot --nginx -d fetchr.download -d api.fetchr.download
```

**سایت باز می‌شود ولی لینک‌ها کار نمی‌کنند:** فایل‌های سایت با آدرس API ساخته می‌شوند. اگر دامنه‌ی API چیزی غیر از `api.fetchr.download` است، در گیت‌هاب در Settings ← Secrets and variables ← Actions ← Variables متغیر `WEB_DEFAULT_API` (مثلاً `https://api.example.com/`) و `WEB_HOST` را تنظیم کنید و یک نسخه‌ی جدید منتشر کنید.

## حذف کامل

```bash
cd /opt/fetchr && sudo docker compose --profile '*' down -v
sudo systemctl disable --now fetchr-monitor.timer
sudo rm -f /etc/systemd/system/fetchr-monitor.*
sudo rm -rf /var/lib/fetchr-monitor
sudo rm -f /etc/nginx/sites-enabled/fetchr-*.conf /etc/nginx/sites-available/fetchr-*.conf
sudo nginx -t && sudo systemctl reload nginx
sudo rm -rf /opt/fetchr /var/www/fetchr
```

## انتشار نسخه‌ی جدید (برای توسعه‌دهنده)

با ساختن یک release در گیت‌هاب با تگی مثل `v1.0.0`:
